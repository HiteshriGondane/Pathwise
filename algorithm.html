02 / ALGORITHM

How UCS works

Start with cost 0, repeatedly select the lowest-cost frontier path, and update neighbours whenever a cheaper route is found.

Algorithm steps

  1. Put the start node in a priority queue with cost 0.
  2. Remove the entry with the smallest total cost.
  3. If it is the goal, return its path and total cost.
  4. For each neighbour, calculate new cost = current cost + edge cost.
  5. If this is a better cost, update the neighbour and add it to the queue.
  6. Repeat until the goal is found or the queue is empty.
Pseudocode
UCS(start, goal):
    priorityQueue ← [(0, start)]
    bestCost[start] ← 0
    parent[start] ← null

    while priorityQueue is not empty:
        (cost, node) ← removeMin(priorityQueue)

        if cost ≠ bestCost[node]:
            continue

        if node = goal:
            return reconstructPath(parent, goal), cost

        for each (neighbor, edgeCost) of node:
            newCost ← cost + edgeCost

            if neighbor not in bestCost
               or newCost < bestCost[neighbor]:
                bestCost[neighbor] ← newCost
                parent[neighbor] ← node
                insert(priorityQueue,
                       (newCost, neighbor))

    return "No path found"

Formula used by UCS

Use this equation when solving numerical questions.

g(next) = g(current) + c(current, next)

g(next): total cost from the start to the next node.

g(current): best-known total cost from the start to the current node.

c(current, next): cost written on the edge between these two nodes.

UCS rule: remove and expand the valid frontier entry with the smallest g(n). If a cheaper route to a node is found, update its cost and parent.

Mini example: g(A) = 4 and cost(A, B) = 3, so g(B) = 4 + 3 = 7.

Time and space complexity

For a graph with V vertices and E edges, using a binary-heap priority queue.

Time complexityO((V + E) log V)Common graph implementation with a binary heap and suitable decrease/update handling.
Space complexityO(V + E)Graph storage plus best costs, parents, visited/queue entries.
Core data structurePriority queueRemoves the path with the smallest cumulative cost.
Complexity can vary with the priority-queue implementation. With a simple unsorted list, extracting the minimum can take O(V) each time, giving a less efficient bound.
